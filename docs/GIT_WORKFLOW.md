# دليل العمل على Git

هذا الدليل يحدد طريقة العمل على المستودع. اتبعه في كل كرت.

## 1) الفروع

`main`

الفرع المستقر. لا عمل مباشر عليه. يستقبل الدمج من develop فقط في نهاية السبرنت وقبل العرض.

`develop`

فرع التجميع. كل ميزة منتهية تدمج هنا. هو الفرع الافتراضي للمستودع.

`feature/US-04-file-upload`

فرع لكل كرت. ينشأ من develop ويدمج فيه ثم يحذف تلقائيا.

لإصلاح خطأ استعمل هذا الشكل:

`fix/US-04-wrong-mime-check`

قاعدة التسمية: نوع الفرع، ثم رقم الكرت، ثم اسم قصير بالإنجليزية وبأحرف صغيرة وشرطات.

## 2) الحماية على الفرعين main و develop

القواعد التالية مفعلة على الفرعين:

1. لا دفع مباشر. كل تغيير عبر Pull Request.
2. مراجعة واحدة معتمدة تكفي للدمج.
3. صاحب الطلب لا يعتمد طلبه.
4. أي دفعة جديدة بعد الاعتماد تلغي الاعتماد، وتحتاج مراجعة جديدة.
5. كل التعليقات يجب أن تحل قبل الدمج.
6. يمنع الدفع القسري وحذف الفرعين.

## 3) دورة العمل على كرت

الخطوة 1: انقل الكرت إلى In Progress على Trello.

الخطوة 2: أنشئ فرعك من أحدث develop.

```bash
# Get the latest develop
git checkout develop
git pull origin develop

# Create your feature branch
git checkout -b feature/US-04-file-upload
```

الخطوة 3: اعمل وسجل التغييرات. رسالة الحفظ تبدأ برقم الكرت.

```bash
git add .
git commit -m "US-04: add file size validation"
```

الخطوة 4: ادفع الفرع.

```bash
git push -u origin feature/US-04-file-upload
```

الخطوة 5: افتح Pull Request. الوجهة هي develop.

الخطوة 6: انقل الكرت إلى Code Review، وضع رابط الطلب في تعليق على الكرت.

## 4) فتح Pull Request

العنوان يبدأ برقم الكرت:

```text
US-04: Upload CV and LinkedIn files with validation
```

الوجهة (base): develop.

الوصف: املأ القالب الذي يظهر تلقائيا، وضع رابط كرت Trello.

اطلب المراجعة من شخص واحد فقط في خانة Reviewers.

اجعل الطلب صغيرا قدر الإمكان. كرت واحد يعني طلب واحد.

## 5) المراجعة والدمج

يراجع الطلب شخص واحد فقط.

المراجع يتبع هذه الخطوات:

1. يقرأ الكود ويقارنه بمعايير القبول في الكرت.
2. يشغل الطلب ويجربه عند الحاجة.
3. إذا وجد ملاحظات يختار Request changes ويكتب التعليقات.
4. صاحب الطلب يصلح ويدفع على نفس الفرع.
5. عندما يرضى المراجع يختار Approve.
6. بعد الاعتماد، المراجع نفسه يضغط Squash and merge.

قواعد الدمج:

- لا أحد يدمج طلبه بنفسه.
- لا دمج بدون اعتماد.
- لا دمج إذا فشلت الاختبارات.
- بعد الدمج يحذف الفرع تلقائيا.
- بعد الدمج انقل الكرت إلى QA / Testing.

## 6) ما يتأكد منه المراجع

- كل معيار قبول في الكرت يعمل.
- الاختبارات مكتوبة وتنجح.
- لا كلمات مرور ولا رموز تحقق ولا مفاتيح ولا نص سيرة كامل في الكود أو السجلات.
- المسارات الجديدة تستعمل حراس الصلاحيات من كرت US-03.
- الكتابة على أكثر من جدول داخل معاملة واحدة.
- الأخطاء مصنفة: مؤقت أو دائم.
- الأسماء واضحة والكود مقروء.

## 7) تحديث فرعك من develop

قبل فتح الطلب، وكلما تغير develop، أدخل آخر التغييرات إلى فرعك.

```bash
git fetch origin
git merge origin/develop
```

إذا ظهر تعارض (conflict):

```bash
# 1. Open the conflicted files and fix the markers
# 2. Mark them as resolved
git add .
# 3. Finish the merge
git commit
# 4. Push your branch
git push
```

## 8) دمج develop في main

يحدث في نهاية Sprint 1 (7 نوفمبر) وفي نهاية Sprint 2 (15 نوفمبر).

1. افتح Pull Request من develop إلى main.
2. مراجعة واحدة معتمدة.
3. اختر Create a merge commit.
4. بعد 15 نوفمبر لا ميزات جديدة. إصلاحات الأخطاء فقط، عبر فرع fix.

## 9) ممنوع

- الدفع المباشر على main أو develop.
- الدفع القسري (force push).
- دمج طلب بدون مراجعة.
- العمل على فرع بدون رقم كرت.
- رفع ملف .env أو مفاتيح أو كلمات مرور.
- رفع سير ذاتية حقيقية. استعمل بيانات مصطنعة فقط.
